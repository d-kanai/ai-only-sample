# 作業ログは日付のディレクトリの下にブランチごとのファイルで書き、PR どうしの追記の競合をなくす

- 日付: 2026-10-03
- 状態: 採用
- 関連: Issue #441 / Issue #425 / `.claude/rules/workflow/work-log.md` / `.claude/rules/tooling/work-log-hooks.md` / `scripts/hooks/require-work-log.sh` / `scripts/hooks/check-work-logs-diff.sh`

## 背景
作業ログは 1 日 1 ファイル（`docs/work-logs/YYYY-MM-DD.md`）で、どの PR も同じファイルの末尾に追記していた。1 本マージされるたびに残りの PR が競合し、GitHub は競合した PR で CI も auto-merge も動かさず通知も無いので、PR が取り残された（2026-10-03 の work-logs「残っていた PR とスレッドを棚卸しし…」）。同じ日に 1 項目 1 ファイルの案は daiki が見送ったが、競合が続くので daiki が改めて改善を求めた（2026-10-03、プロジェクトのスレッド）。

## 決定
- 作業ログは `docs/work-logs/YYYY-MM-DD/<ブランチ名の / を - にしたもの>.md` に書く（1 日 1 ディレクトリ、1 ブランチ 1 ファイル）。
- Stop フックは今のブランチの今日のファイルを、CI は PR の head ブランチのファイルを要求する。1 日 1 ファイル・別のブランチのファイルでは通さない。
- 過去の 1 日 1 ファイルのログはそのまま残す（記録で、移さない）。
- 読むときは `pnpm work-logs:html`（`scripts/work-log-html.mjs`）で日付ごとに 1 つにまとめた HTML を作る。出力はコミットしない。

## 理由
- 1 つの PR は 1 つのブランチなので、ブランチごとのファイルなら別の PR が同じファイルに書かず、追記どうしが競合しない。
- 1 項目 1 ファイルよりファイルが少なく、日付のディレクトリでその日の記録をまとめて読める。
- ファイル名をブランチ名から機械的に決めるので、フックと CI で置き場所を検査できる（CLAUDE.md の 7.）。

## 採用しなかった案
- `.gitattributes` の `merge=union`: 手元の `git merge` では効くが、GitHub の mergeability の判定と Merge ボタンは merge ドライバを使わないので、PR は競合のまま止まる（https://github.com/orgs/community/discussions/9288 ）。
- 1 項目 1 ファイル: 2026-10-03 に daiki が見送り。ファイルが細かくなりすぎる。
- 1 日 1 ファイルのまま、競合を見つけた人が直す: 競合に気づく仕組みが無く、PR が取り残され続けた。

## 影響
- 良い点: 作業ログの追記で PR どうしが競合しない。マージ後の記録の PR も別のブランチなので競合しない。
- 悪い点: 1 日の記録が複数のファイルに分かれる（読むときは HTML にまとめる。daiki の「そしたら読みづらいなぁ」、2026-10-03）。ブランチに居ない（detached HEAD）ときは Stop フックが判定しない。
- 見直す条件: 1 つのブランチを複数のスレッドで同時に使うようになったとき（同じファイルに追記して競合しうる）。
